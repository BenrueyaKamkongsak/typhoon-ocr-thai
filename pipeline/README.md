# Thai OCR Pipeline (prototype)

ระบบแปลงเอกสารสแกนภาษาไทยจำนวนมากเป็นข้อมูลที่คลีนแล้ว ตัวอย่างนี้ใช้กับ **ประกาศผู้ชนะการเสนอราคา** ของหน่วยงานรัฐ

```
โฟลเดอร์ไฟล์ → แยกหน้า → OCR (Typhoon, รันขนาน, มี cache) → ดึงฟิลด์ → คลีน → ตรวจคุณภาพ
                                                                       ├─ ผ่าน  → documents.csv / bidders.csv → โหลดเข้า DB
                                                                       └─ ไม่ผ่าน → review_queue.csv → ให้คนตรวจ
```

## ทำอะไรได้บ้าง

| ขั้น | รายละเอียด |
|---|---|
| รับไฟล์ | JPG, PNG, WebP, TIFF, PDF หลายหน้า ทั้งโฟลเดอร์ (รวมโฟลเดอร์ย่อย) |
| ข้าม OCR เมื่อทำได้ | PDF ที่มี text layer ใช้ข้อความตรง ๆ **แต่ตรวจก่อนว่าภาษาไทยไม่เพี้ยน** (สระ/วรรณยุกต์ลอยแยกจากพยัญชนะ ซึ่งพบบ่อยใน PDF ราชการ) ถ้าเพี้ยนจะส่งไป OCR แทนอัตโนมัติ |
| OCR | Typhoon OCR ผ่าน API (prompt เดียวกับ client ทางการ v1.5), ส่งหลายหน้าพร้อมกัน, retry เมื่อเจอ 429/5xx, หยุดทันทีถ้า key ผิด |
| Cache | เก็บผล OCR ตาม hash ของไฟล์ + หน้า ไฟล์เดิมไม่ถูกส่งซ้ำ รันซ้ำจะ OCR เฉพาะหน้าที่เคยล้มเหลว |
| ดึงฟิลด์ | หน่วยงาน, โครงการ, วิธีจัดซื้อ, ผู้ชนะ, วงเงิน (ตัวเลข+ตัวหนังสือ), วันที่ประกาศ, ตารางผู้เสนอราคา (รองรับเซลล์ผสาน) |
| คลีน | เลขไทย → อารบิก, พ.ศ. → ค.ศ. (ทั้ง "14 ตุลาคม พ.ศ. 2569" และ "๒๘ ต.ค. ๖๙"), แปลงจำนวนเงินตัวหนังสือเป็นตัวเลข, แยกประเภทนิติบุคคล (หจก./บจก./บมจ./ร้าน) |
| จับคู่บริษัท | เทียบชื่อผู้ชนะกับทะเบียนบริษัท (CSV `id,name`) แบบ fuzzy เช่น "หจก. ทดลองก่อสร้าง" = "ห้างหุ้นส่วนจำกัด ทดลองก่อสร้าง" |
| ตรวจคุณภาพ | วงเงินตัวเลข ≠ ตัวหนังสือ, ผู้ชนะไม่อยู่ในตาราง, ราคาผู้ชนะในตาราง ≠ วงเงินที่ประกาศ, ฟิลด์จำเป็นขาด, วันที่อ่านไม่ได้, OCR ล้มเหลว → ส่งเข้าคิวตรวจ |

## ผลลัพธ์ (ในโฟลเดอร์ `--out`)

- `documents.csv` หนึ่งแถวต่อเอกสาร พร้อม `status` (ok / review), `errors`, `warnings`
- `bidders.csv` ผู้เสนอราคาทุกราย พร้อมราคาครั้งแรก/ต่อรอง และธงผู้ชนะ
- `review_queue.csv` เฉพาะเอกสารที่ต้องให้คนตรวจ พร้อมเหตุผล
- `markdown/` ผล OCR ของแต่ละไฟล์ ไว้ย้อนดูที่มาของทุกค่า
- `run_report.json` สถิติ: จำนวนไฟล์/หน้า, cache hit, จำนวนครั้งที่เรียก OCR, เวลา

CSV เขียนเป็น UTF-8 with BOM เปิดใน Excel แล้วภาษาไทยไม่เพี้ยน

## ลองรัน

```bash
cd pipeline
pip install -r requirements.txt

# ทดลองโดยไม่ต้องมี API key (ใช้ผล OCR ที่บันทึกไว้ใน examples/fixtures)
python -m thai_ocr_pipeline --input examples/inbox --out out --backend fixtures \
    --fixtures examples/fixtures --master examples/company_register.csv

# ใช้ Typhoon จริง
export TYPHOON_API_KEY=...   # สมัครฟรีที่ https://playground.opentyphoon.ai
python -m thai_ocr_pipeline --input /path/to/scans --out out --workers 4 \
    --master company_register.csv -v

# ทดสอบ
python -m pytest -q
```

ตัวเลือกอื่น: `--cache DIR` (ใช้ cache ร่วมกันข้ามการรัน), `--force-ocr` (OCR ทุกหน้าแม้ PDF มี text layer),
`--model` / `--base-url` (เปลี่ยนเป็นเซิร์ฟเวอร์ Typhoon OCR ที่ติดตั้งเองด้วย vLLM ได้ เพราะเป็น API แบบ OpenAI-compatible)

## ตัวอย่างใน `examples/`

เอกสารทั้งหมดเป็นของสมมติ สร้างด้วย `examples/make_examples.py`

| ไฟล์ | ผลที่คาดไว้ |
|---|---|
| 01-ถนน-คสล-บ้านทดลอง.jpg | ok ทุกอย่างตรงกัน |
| 02-ครุภัณฑ์คอมพิวเตอร์-ทต-ตัวอย่าง.jpg | review: 1,250,000 บาท แต่ตัวหนังสือเขียน "หนึ่งล้านสองแสนบาทถ้วน" |
| 03-ฝายน้ำล้น-บ้านทดลอง.jpg | ok: ใช้ชื่อย่อ "หจก." และเลขไทย แต่ยังจับคู่กับทะเบียนได้ |
| 04-สแกนเสีย-ไม่มีผลOCR.jpg | review: จำลองหน้าที่ OCR ล้มเหลว |
| 05-วัสดุการแพทย์-ไฟล์ดิจิทัล.pdf | ok: PDF มี text layer แต่ภาษาไทยเพี้ยน จึงถูกส่งไป OCR อัตโนมัติ |

## ใช้กับ Airflow

`airflow/dags/thai_ocr_dag.py` รันทุกวัน: OCR+คลีน → โหลดเฉพาะเอกสาร ok → แจ้งคิวตรวจ
ตั้งค่าผ่าน Airflow Variables (`thai_ocr_inbox`, `thai_ocr_out_root`, `thai_ocr_cache`, `thai_ocr_master`)
และใส่ `TYPHOON_API_KEY` ใน environment ของ worker ส่วนโหลดเข้า DB และแจ้งเตือนเป็นจุดที่ต้องเติมตามระบบจริง

## ข้อจำกัดของ prototype

- ตัวดึงฟิลด์เป็นแบบกฎ (regex + ตาราง) ออกแบบมาสำหรับประกาศผู้ชนะ เอกสารประเภทอื่นต้องเพิ่มกฎ หรือเปลี่ยนเป็นให้ LLM ดึงฟิลด์ตาม schema
- ทดสอบกับผล OCR ที่จำลองไว้ ยังต้องวัดความแม่นกับเอกสารจริงและผล Typhoon จริง ควรเตรียมชุดเอกสารที่ตรวจด้วยมือแล้วไว้วัดผล
- Typhoon API ส่งไฟล์ออกนอกองค์กร เอกสารลับควรติดตั้ง Typhoon OCR เองบนเครื่องที่มี GPU (โมเดล Apache-2.0)
